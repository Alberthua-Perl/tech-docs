## 第一部分：问题诊断 - 稠密/稀疏检索与 RRF 融合

### 1.1 原始代码状态

- **稠密检索**：在 `src/retrieval/hybrid_engine.py` 中通过 `VectorIndexRetriever` 实现。
- **BM25 稀疏检索**：项目代码中未显式实现，仅在 `src/ingestion/index_manager.py` 的 `MilvusVectorStore` 初始化参数里写了 `hybrid_ranker="RRFRanker"`。
- **RRF 融合**：仅通过 `MilvusVectorStore` 参数配置，没有真正发起 hybrid search 请求。

### 1.2 关键结论

> 仅在 `MilvusVectorStore` 中配置 `hybrid_ranker="RRFRanker"` 不足以实现真正的 BM25 + RRF。真正的 hybrid search 需要：
> 1. 集合 schema 包含 sparse 字段
> 2. 创建 sparse 索引
> 3. 写入时生成 sparse vector（或使用 BM25 内置函数）
> 4. 查询时同时传入 dense 和 sparse 查询请求
> 5. 由 Milvus 执行 `hybrid_search` + ranker 融合

## 第五部分：注意事项

1. **首次启动需重新索引**：启用 sparse 后集合 schema 已改变，旧集合会在 `IndexManager` 初始化时自动删除重建。
2. **RAGAS 调用成本**：启用后会额外调用 LLM 和 Embedding API，单次评估约 20–50 秒，会产生额外费用。
3. **API Key 配置**：项目根目录 `.env` 文件中的 `API_KEY` 和 `API_BASE_URL` 会被自动加载。
4. **依赖冲突**：安装 ragas 过程中可能升级 numpy/scipy，已调整 `requirements.txt` 与之匹配。
